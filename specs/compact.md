## 0. Purpose and mods
Cut spend by compacting at the right moment, hand work over without losing it, and keep an Opus-orchestrator discipline alive across compaction. Opus 5.5 auto-compacts only near ~967k (10), so big sessions never compact on their own and pay the whole context every turn.
Mods: `coach` (Carrot, cost cast), `handoff`, `resume`, `orch`. Band row (own row, see 4). Commands (3): `/handoff`, `/coach`, `/orch`; collision rule of 00 section 1.6 (`compact-handoff`...). No panes, no skills, no tools, no agents. Toast: one (Coach), limiter per 00 section 7.5. Tokens spent by the plugin: zero, except the one prompt `/handoff` sends on purpose (model writes the file) and the compaction the user confirms.
the user's rule ("don't fill my context"): everything is 0 tokens except the Orchestrator section (section 8), which the user chose to have ON by default (12.5); the suite always-loaded cap is raised to 500 tokens to hold it. `/orch off --yes` returns the footprint to 0.

## 1. Compact Coach (`coach`)
**Behaviour.** Band chip when `ctx >= coach.showFromTokens` (100k) or a handoff is in progress. Shows: context size, est. cost per turn now (warm and cold), est. cost per turn at the target, saving per turn, payback in turns, and the moment verdict with its reasons. Pure estimate, labelled `estimate (prices as of 2026-10-11)`. Dollars are a yardstick; subscription quota weights are unpublished (12d s1).
**Moment score (0..8).** +3 cache cold, or expiring within `cache.expiringSec`; +2 phase just finished; +2 no running agents; +1 user returned from idle (a turn starts after a gap >= `coach.idleReturnMin` 10). Verdict: >=5 `GOOD MOMENT`, 3-4 `OK`, <3 `NOT NOW`. Gates (verdict forced `NOT NOW`, chip shows why): ctx < showFromTokens; saving per warm turn < `coach.minSavingUsd` 0.02; a handoff in `compacting`. Running agents > 0 removes the +2 and appends `agents running` (never blocks; /handoff lists them).
**Signals (read, never duplicated).** Cache: `usage.cache.state` (`warm|expiring|cold|unknown`), `ttl`, `expiresAt` from usage.md s5; absent atom = 0 points and `cache ?`. Phase finished: `awareness.now.phase === 'report'` or `awareness.now.isComplete`, or `awareness.now.specTotal>0 && specDone===specTotal` (Spec Tracker), or the Mission Board "all done" atom `agents.mission.allDone` (defined in `mission-board.md` section 4; absent = no information). Agents: `$.agent.list()` entries with status `pending|running|waiting` (T:3187, T:539), refreshed on `turn.complete` and every 30 s while the chip shows. Idle return: own stamp of last `prompt.submit` and last `turn.complete`.
**Toast.** One Heads-Up-style toast per strong episode: `COMPACT · good moment at 350k. Saves ~$0.06/turn. Run /handoff.` (<= 140 chars). Offered only when verdict >= 5, no handoff in progress, and not within `coach.toastMinGapMin` 20 of the last Coach toast; re-arms when the score falls below 3 or after a compaction. `createLimiter({minGapMs:60000, peers:['awareness.headsup','dev.toast']})`; publishes `compact.coach.lastShownAt`; quiet while `awareness.focus.phase==='focus'` or `headsup.mutedUntil` is in the future.
**Payback line** (formula section 5): `compaction pass ~$0.47 · pays back in ~8 warm turns`; cold: `cold now: pass ~$2.15 < next turn ~$2.80 · pays back at once`. `/coach` prints the full card (inputs, both formulas, prices source and date, signals and points).
**Strings (terminal; desktop `alt` identical).**
```

🥕 CTX 350k · $0.07→$0.01/turn · ~8 turns · ✅ GOOD MOMENT · /handoff
```

Handoff states replace the verdict: `📋 HANDOFF writing → handoff/2026-10-11-mods-session.md`, `📋 HANDOFF ready · compaction is irreversible · /handoff go (~$0.47) or /handoff cancel`, `📋 HANDOFF saved (no compact)`, `COMPACTED 351k → 41k`, `⚠ HANDOFF incomplete: missing Decisions`. NOT NOW: `⚠ NOT NOW · task in progress`. Meter: 12 cells `round(score/8*12)`. Glyphs only from 00 section 6 (no new glyph).
**Wireframe (desktop, one `Svg` row 30 px, Carrot 32 px).** `CTX 350K` Silkscreen 10 px, then Space Mono 10 px `$0.07 → $0.01 /turn · save $0.06`, a bevelled tile `GOOD MOMENT` with ok edge (`OK` warn-dim, `NOT NOW` dim), 12-cell meter, reason glyph text. Variants px/cells: full 720/118; no meter 520/84; chip+save 300/46 (`CTX 350k · save $0.06/turn · GOOD`); chip only 130/22 (`🥕 350k ✅`). **Options.** `coach.showFromTokens` 100000, `coach.targetTokens` 40000, `coach.summaryOutTokens` 4000, `coach.handoffOutTokens` 3000, `coach.minSavingUsd` 0.02, `coach.strongAt` 5, `coach.idleReturnMin` 10, `coach.toast` true, `coach.toastMinGapMin` 20, `coach.passAssumesCacheHit` true, `pricesJson` (plugin-level, schema of agents.md s4 plus `write1h`).

## 2. /handoff (`handoff`)
**Flow.** (1) `/handoff [slug]` or `/handoff --no-compact [slug]`: resolve path, build prompt, `await $.prompt.submit({text})` (T:2939; it queues and resolves when the turn STARTS, not ends, R:163), state `writing`. (2) Detect done: first main-loop `turn.complete` with `reason==='answer'` after our submit (T:4464, T:13324-13330), then `$.fs.exists(path)` and `$.fs.stat.size >= handoff.minBytes` (800) and `$.fs.read` shows all eight headings of section 2.3. Else state `failed` with the one fix (`ask again: /handoff retry`); 3 failures stop. (3) Normal mode: state `ready`, a `$.ui.notice` line plus the chip show the confirm text; nothing compacts. `/handoff go` within `handoff.confirmTtlMin` (30) of ready runs `$.session.compact({instructions})` (T:2864-2875): state `compacting`, then `done` with `tokensBefore/After` from the result (T:10753-10777; absent: next `session.measure`). `/handoff cancel` or expiry returns to idle; the file stays. `--no-compact`: stops at `saved`, never offers `go`.
**Why two steps.** Compaction is irreversible; the file write is not. `go` is typed by the user only; no timer, hook or toast ever calls `compact`.
**2.1 Path.** `<repo>/handoff/<YYYY-MM-DD>-<slug>.md` where repo = git toplevel of cwd (`git rev-parse --show-toplevel` via `proc.ts`, else walk up for `.git` with `$.fs.exists`); outside a repo `~/.local/state/claude-handoffs/<date>-<slug>.md` (home from `printenv HOME` via `proc.ts`; `~` expansion in `$.fs` UNVERIFIED so never relied on). Slug = kebab-case of the argument, else of the session title (`$.session.usage`/state, UNVERIFIED field) else `session`; max 40 chars; existing file gets `-2`, `-3`. The directory is created by `$.fs.write` semantics (T:3249) only if the model writes it; the plugin never writes the handoff body itself.
**2.2 Prompt sent (one-shot, ~300 tokens, framed as a plugin message).** Asks the model to Write exactly `{path}` with the template of 2.3, "enough that a fresh model with no memory can continue", real paths, no secrets, no tool output dumps; lists the currently running agents `{id}: {description}` read from `$.agent.list()` as a seed ("for each, say what to do with its report"); ends "Do nothing else this turn."
**2.3 Template (fixed headings, from the 2026-10-11 example).** First line `# Handoff: {title} ({date})`, second `Read this whole file before doing anything else. It replaces the conversation history compaction removed.` Then: `## 1. Goal`; `## 2. User preferences and standing rules` (model policy, how to ask questions, style); `## 3. What exists (with paths)`; `## 4. Verified facts (do not re-derive)`; `## 5. Decisions (closed and open)`; `## 6. Running background agents` (id, task, output file, what to do with the report; "none" allowed); `## 7. Next steps (in order)`; `## 8. Resume prompt` (a paste-ready prompt).
**2.4 Compaction instructions.** "Keep one fact above all: the handoff file at {path} is the source of truth and must be read first. Name the path and the running agent ids. Keep decisions and the next step. Drop detail that file already holds." Passed as `instructions` (T:10741-10750).
**Edge cases.** A turn running: `$.session.compact` rejects (T:2866): state stays `ready`, text `Turn running. Run /handoff go when it ends.` A hook veto returns `{skip}`: show the reason, state `ready`. `/handoff go` with nothing ready: `Nothing to compact. Run /handoff first.` Agents finishing mid-write are fine (their turns queue). `-p` run: commands answer text only, no chip.

## 3. Resume loader (`resume`)
**Trigger (verified).** `session.start` carries NO `source` (T:11671); `source: 'compact'` exists only on the classic `SessionStart` input (T:11645), and whether `classic.SessionStart` fires after an in-session compaction is UNVERIFIED. So the trigger is the `session.compact` event: after `await next(e)` resolves a `SessionCompacted` (not `skip`, trigger not `precompute`, no `agentId`; T:10753, T:10792-10850) it writes `compact:pending:<sid>` = `{v:1, path, at, savedAt}` when this session saved a handoff within `handoff.resumeMaxAgeMin` (240), whatever the trigger (manual, auto or plugin). `/handoff go` also sets it after its own awaited result (idempotent), covering a plugin-trigger event that does not reach our own hook (UNVERIFIED).
**Injection.** A `prompt.submit` hook (T:9051-9075, `context` T:9068) appends ONE entry to `e.context` on the first user prompt after compaction, then deletes the pending key: `Context was compacted. Read {path} first, then continue from its "Next steps". Handle background agent reports as that file lists.` (<= 60 tokens, ~35). It rides in the user message, so the system prompt and cache prefix are not touched. If the file is gone at that moment: inject nothing, `$.ui.log` once. Background agent completions keep arriving and the model continues from the file because (a) the compaction summary names the path (2.4) and (b) the entry above. Whether `prompt.submit` fires for a task-notification turn is UNVERIFIED; fallback is (a). Not a `prompt.compose` section on purpose: adding then removing a system section would change the prefix twice.

## 5. Cost maths (list prices 12d s2, as of 2026-10-11, USD/MTok; `shared/prices.ts` `price(model)`, `writePrice(model, ttl)`)
Symbols: C context now; C' target (section 1 floor rule); R cache read; W1 = 1h write (main conversation on subscription, 12d s5), W5 = 5m write (compaction and helpers, 12d s5); O output; S = summary output tokens (4000); H = handoff output tokens (3000). Input-side only: output per turn is equal either way.
- warm turn `Tw = C*R`; cold turn `Tc = C*W1`; after compaction `Tw' = C'*R`, `Tc' = C'*W1`.
- saving per warm turn `s = Tw - Tw'`; per cold turn `Tc - Tc'`.
- compaction pass `P_warm = C*R + S*O + C'*W1` (summary reads the warm prefix, then the first turn writes the new prefix); `P_cold = C*W5 + S*O + C'*W1` (UNVERIFIED that the pass can reuse the main cache prefix, 12b says `/compact` busts it; option `coach.passAssumesCacheHit` false prices the warm pass as `C*W5` too).
- handoff turn `H_warm = C*R + H*O`; `H_cold = C*W1 + H*O` (it also re-warms the cache, so the pass after it is `P_warm`).
- payback turns: smallest `n` with `baseline(n) >= compacted(n)`, where baseline(n) = `Tw*n` warm, or `Tc + Tw*(n-1)` cold; compacted(n) = `P_total + Tw'*(n-1)`; warm closed form `n = ceil((P_total - Tw')/s)`.
**Worked example, Opus 5.5 (R 0.20, W1 8, W5 5, O 20), C = 350k, C' = 40k, S = 4k, H = 3k.**
`Tw` = 350,000*0.20/1e6 = **$0.070**; `Tc` = 350,000*8/1e6 = **$2.80** (40x); `Tw'` = **$0.008**; `Tc'` = 40,000*8/1e6 = **$0.32**; `s` = **$0.062**.
`P_warm` = 0.070 + 4,000*20/1e6 (0.080) + 0.32 = **$0.47**; `P_cold` = 350,000*5/1e6 (1.75) + 0.08 + 0.32 = **$2.15**; `H_warm` = 0.07 + 0.06 = $0.13; `H_cold` = 2.80 + 0.06 = $2.86.
| path | total P | payback |
|---|---|---|
| `/compact`, warm | $0.47 | ceil(0.462/0.062) = **8 turns** |
| `/compact`, cold | $2.15 | **turn 1** (2.15 < 2.80, nets +$0.65) |
| `/handoff` + compact, warm | 0.13 + 0.47 = $0.60 | ceil(0.592/0.062) = **10 turns** |
| `/handoff` + compact, cold | 2.86 + 0.47 = $3.33 | **10 turns** (0.062*(n-1) >= 0.53) |
After payback, 30 more warm turns: baseline 30*0.07 = $2.10, compacted via handoff 0.60 + 29*0.008 = $0.83, net **$1.27 saved**. Reading: compacting while cold is the cheapest moment; with the handoff step, cold is no cheaper than warm because the handoff turn pays the cold rewrite first (Coach prints that). Sonnet 5.5 (R 0.10, W1 4) halves every figure. Quality loss of compaction is not priced.

## 6. Orchestrator mode (`orch`) — default ON (the user's decision, 12.5), switchable off
**Behaviour.** `/orch on|off|status` (persisted `$.store['orch:on']`, `{v:1,on}`; option `orch.enabled` is the first-run default, true; once the store key exists it wins). When on, a `prompt.compose` hook (T:4184, T:8354-8400) appends one section `{id:'compact:orchestrator', scope:'session', text}` after `await next(e)`; engine sections are never edited. Because the engine re-composes for every request (T:2989), it survives compaction with no re-injection and no `SessionStart` hook; the text is constant so it adds no cache churn after the first turn. Because it is ON from the first session, the section is part of the prefix from the start and costs no extra cold turn at install. Toggling later changes the system prompt and costs one cold turn (350k: $2.80 on Opus 5.5, 12b); `/orch on|off` says so and asks for `--yes` (`/orch on --yes`), otherwise prints the estimate and does nothing. Prefer toggling right after a compaction or at session start.
**Text (<= 480 chars, ~100 tokens, counted by the contract).**
`Orchestrator mode. You reason, decide, spec and review. Sonnet builds (code, tests, fixes, docs, git). Haiku gathers (search, reading, bulk extraction). Opus or Fable subagents only for hard reasoning; say why. ALWAYS set model explicitly on every Agent call. One scoped brief per agent: goal, files, constraints, acceptance check, output format. Review results, do not redo them. Parallelise independent work.`
**With Delegation Guard (agents.md s4).** The section asks for an explicit model; Guard in `warn`/`deny` mode checks it (`NO MODEL SET`); this mod never reads or changes Guard state and works with Guard absent.
**`CLAUDE_CODE_SUBAGENT_MODEL_FORCE` (10 vs 12b).** Precedence (10): per-call `model` > agent frontmatter > `CLAUDE_CODE_SUBAGENT_MODEL` > main model. `_FORCE=1` (v2.1.257+) makes the env var beat the per-call model, so it caps spend hard, but it also blocks deliberate escalation to Opus/Fable and overrides frontmatter. **Recommendation: do NOT force.** Keep `CLAUDE_CODE_SUBAGENT_MODEL=sonnet` as the fallback for calls without a model, this section as the instruction, and Guard `deny` as the enforcement (it blocks a missing model, not a chosen one). `/orch status` prints whether the env var is set (`$.settings.read()` env, T:3578, else unknown) and that FORCE is not recommended. The mod never sets env or settings.

**F35.1 Section hashes in the meta.** `<sid>-agent.meta.json` (F33.4) gains, all optional and ignored by older readers: `sections` = `{ "<heading text without ##>": "<hash>" }` for the six F33 headings; `prevSections` (the `sections` of the nudge before); `userTurns` and `toolCalls` (main-loop counts since the last delivered nudge: one `prompt.submit` with non-empty text = one user turn; one main-loop `tool.call`, any tool, = one tool call; subagent events never count); `lastUserMsgAt` (epoch ms of the latest main-loop `prompt.submit`); `stale_sections` (array of heading names, `[]` or absent when none). `v` stays 1. Hash = first 12 hex chars of SHA-256 over the section body: the bytes after the heading line up to (not including) the next line that starts with `## ` or end of file, with trailing whitespace removed and `\r\n` normalised to `\n`. A heading missing from the file has hash `absent`. Parsing is by exact heading line equality with the six strings of `HEADINGS` (`mods/nudge.tsx:4`). Constants (named, `mods/nudge.tsx`): `STALE_USER_TURNS = 3`, `STALE_TOOL_CALLS = 40`, `FRESH_GRACE_MS = 600000`.

**F35.2 Staleness rule (A).** At nudge arm time (`session.measure`, where `$.fs` reads are allowed, F33.3), when the agent file exists: compute `cur` section hashes; set `prevSections := sections`, `sections := cur`. The file is marked stale when ALL hold: a previous nudge was delivered (`prevSections` present), `cur["Exact next step"] == prevSections["Exact next step"]` AND `cur["In progress"] == prevSections["In progress"]` (both byte-identical per F35.1), and since that previous nudge `userTurns >= 3` OR `toolCalls >= 40`. Then `stale_sections = ["In progress", "Exact next step"]` (always both, fixed order); otherwise `[]`. `userTurns` and `toolCalls` reset to 0 at each delivery after the check. A change in only one of the two headings is NOT stale (the AND is deliberate: an agent that rewrote either one looked at the state). Other headings changing (e.g. appended notes in "Done") never clear staleness. A write to the agent file clears nothing by itself: only the next arm-time comparison can; but a detected write whose resulting hashes of both headings differ from `sections` sets `stale_sections = []` at once. Meta write failures are logged once and never block (F33.4).

## F36 Degraded handoff alert (2026-10-16)
Draft for approval. Why: a compaction whose handoff is missing, stale or partly failed must never be silent. The hooks (specs/handoff-hooks-spec.md "F36 Handoff reliability") write `<sid>-degraded.json` into `~/.local/state/claude-handoffs/` when the handoff of a compaction is DEGRADED (hook-spec F36.D: section errors, stale sections, no fresh agent file with no working Haiku fallback, or a missing/old handoff at inject). A REDUCED handoff (no fresh agent file but the Haiku fallback succeeded, no errors; decided by the user 2026-10-16) writes no file, so this plugin shows nothing for it: no toast, no chip. This plugin reads it and tells the user, once, with a toast and a band chip that stays until the problem is fixed. Reasons are the human texts of the hook spec F36.D (`no agent handoff`, `agent handoff stale`, `Haiku fallback failed`, `Haiku fallback timed out`, `sections unavailable: <names>`, `no health record for this compaction`, `no handoff file for this session`, `handoff not refreshed for this compaction`), joined by `; `. This is a new mod `handoffalert` in the `compact` plugin. It adds NOTHING to the model's context (the model-facing warning is written by the hook into `additionalContext`); plugin version bump 1.1.0 -> 1.2.0 (new mod).

**F36.1 File contract (read side).** `<home>/.local/state/claude-handoffs/<sid>-degraded.json` (home from `$.env.get('HOME')`; `<sid>` = `$.session.id()` with `/` replaced by `_`): `{v:1, sid, ts, reasons:[codes], trigger, detected_by, clearedAt?}`; `ts` and `clearedAt` ISO-8601 UTC strings in the file, epoch ms inside the plugin. The plugin reads it with `$.fs` and never deletes it: it marks it cleared by rewriting the same JSON with `clearedAt` set (`$.fs.write`; failure is logged once and the alert state is still cleared in memory). A missing, unreadable, non-object, `v` != 1 or `ts`-less file is "no alert" (one log line for unreadable; never a toast about the file itself).

**F36.2 When it is read.** (a) `session.start` (covers resume and a new process after compaction); (b) after a `session.compact` that is not `skip`, not `precompute`, has no `agentId` (any trigger: manual, auto, plugin), awaited like Resume (F33.11); (c) because the inject hook runs slightly after the compaction event, up to 3 further reads, one on each of the next 3 `session.measure` events (rate: at most one read per 5 s), until a file with `ts` later than the compaction time is found or the 3 reads are used; (d) on each `prompt.submit` while the alert is active (to detect clearing). **F36.3 Alert state.** `alert = {active, reasons, ts}` is active iff the file is valid, `clearedAt` is absent, and `ts` is later than the last clear. The alert is per session id and survives a restart of the process (it re-reads the file at `session.start`).

**F36.4 Toast.** On a transition to active (or the first read at `session.start`/after compaction that finds an active file whose `ts` has not been shown), exactly one toast: `HANDOFF DEGRADED · <reasons joined "; ">`, truncated to 140 chars with `...`. Shown at most once per `(sid, ts)`; the shown `ts` is kept in the store key `handoff:degradedShown:<sid>` (`{v:1, ts}`; no text). It uses the same toast queue and peer-gap rules as the Coach toast (statement 9) but is NOT subject to the Coach 20-minute episode rule, `coach.strongAt`, the verdict, or `coach:toast` (`lastShownAt` is not written). A focus phase or `headsup.mutedUntil` delays the toast (queued, not dropped); the chip below is shown regardless.

**F36.5 Band chip.** While active, the `AbovePrompt` band (one hook, 00 s4.1) carries one extra segment `HANDOFF DEGRADED` (warning colour), placed first, before the `[coach]` segment; in the `$.ui.status` no-band fallback (F30 rule: only while `$.session.surfaces()` is empty) the status text is prefixed `HANDOFF DEGRADED · `. It shows the first reason only (`HANDOFF DEGRADED · no agent handoff`; `+n` appended when more) and is at most 60 chars. It does not change the Coach verdict, score, `reasons` or gate.

**F36.6 Clearing.** The alert clears (chip removed, atom updated, file rewritten with `clearedAt`) when, after the file's `ts`: (a) the user ran `/handoff` and the store key `handoff:last:<sid>` has `savedAt` later than `ts` (a `--no-compact` or cancelled `/handoff` that did save a file counts, as in statement 43); or (b) the agent file is FRESH by the F35.4 rule evaluated at a `prompt.submit` or measure (meaning the agent has rewritten it after the compaction: `agentWrittenAt` later than `ts` AND the F35.4 `isFresh` holds); or (c) the file's `ts` is replaced by a newer compaction's degraded file (then it is a NEW alert with a new toast) or the newer compaction produced no degraded file (cleared, `clearedAt` not written because the hook overwrote the file). A user dismissal command does not exist. Clearing never shows a toast.
