## 0. Rename decision (Q7, decided 2026-10-11)

## 3. Review Queue (`review`)
**Behaviour.** A subagent that finished (done or failed) while the session was open enters the queue until the user marks it reviewed. Each item: description, tier, duration, files touched, test outcome, state. Sorted: FAILED, UNTESTED, TESTS FAILED, TESTS PASSED, NO EDITS, then oldest first. Pane section `REVIEW QUEUE (n)` with a Carrot-with-clipboard still as the section header mascot (40 px, clipboard drawn over the Carrot still: rects in a 40x40 box: edge `2,22,7,10`, plate `3,23,5,8`, gold `4,22,3,2`, ink lines `4,26,3,1` and `4,28,3,1`, as the board's `carrot-clip`). Marking is MANUAL ONLY (Q8): item button `REVIEWED` (desktop Button, terminal `[ reviewed ]`) or `/review done [id|all]`. Nothing is ever marked automatically: not on a later prompt, not on a read of the touched files, not on a timeout; an item leaves the queue only by one of those two actions. Band segment `REVIEW {n}` (terminal `📥 3 to review`); after `remindMin` 10 the segment gets a warn edge and ` · oldest 12 min`. No toast (`review.toast` false; Heads-Up is the nudge channel).

Clarification (2026-10-15, acceptance F31): a test outcome (`12 pass 3 fail`, states TESTS PASSED / TESTS FAILED) comes only from a Bash tool call that invokes a test runner (pytest, vitest, jest, bun test, go test, cargo test/nextest, npm/pnpm/yarn test) AND whose result contains a parsed runner summary. Output of other commands (cat, grep, rg, sed, echo, ls, find, git ...) is never parsed, even if it contains text such as `3 failed, 12 passed`, and a runner name that is only an argument or quoted text of such a command (`grep vitest x.md`) is not a test run. The agent's final report text and Write/Edit contents are never parsed. An agent with no qualifying run is UNTESTED (it wrote files) or NO EDITS (it did not). Test 13b.
**Data.** CONFIRMED: `turn.complete{agentId}` for end and `usage` (T:13315); subagent `tool.call` events carry `agentId` (T:194): count successful Edit/Write/NotebookEdit calls per agent -> files touched (distinct `file_path`/`notebook_path`, T:16278, T:16792, T:16402); Bash results `stdout`/`stderr` (T:20352) parsed by `shared/testparse.ts` (pytest, vitest, jest, bun test, go test, cargo test; same parser as `dev` Test Pulse, see dev.md section 5) -> `{pass, fail, skip}` sums per agent. Not UNVERIFIED: only that a model-spawned subagent's `tool.call` reaches this plugin's hook (AP's own comment relies on it; a subagent spawned through another plugin's `$.agent.spawn` steps past that plugin only).
**States per item.** `failed` (reason != answer), `untested` (>= 1 file touched, no test run), `tests-failed` (last run fail > 0), `tests-passed`, `no-edits` (nothing touched, no tests), `reviewed`. Reviewed items leave the queue and stay in Done.
**Commands.** `/<review-cmd>` lists (numbered); `/<review-cmd> done <id>` marks the item with that list number, `/<review-cmd> done all` marks every queued item, bare `/<review-cmd> done` marks nothing and prints `Usage: /<review-cmd> done <id|all>` (where `<review-cmd>` is the name that actually registered: `review`, or `agents-review` when the host refuses `review`) (no guessing, Q8); an unknown id prints `No queue item {id}`. **Edge cases.** Agents first seen through `$.agent.list()` (backfilled, `isBackfilled`) are not queued unless `review.includeBackfilled`. Teammates that wake again re-enter the queue as unreviewed. State is in-session only (a queue that survives sessions would be stale). **Options.** `review.remindMin` 10, `review.includeBackfilled` false, `review.toast` false.

## 4. Delegation Guard (`delegation`)
**Behaviour (policy: `~/.claude/CLAUDE.md` "Always set model explicitly"; Delegation Guard OWNS the "Agent without model" toast, Q3; its pane header mascot is Carrot with the clipboard, Q9).** Hook `agent.spawn` BEFORE `next`. Missing model = `e.model === undefined` (T:303) for a spawn that is not `subagentType === 'fork'` (forks ignore model) and whose type does not match `allowTypes` (glob, default `savvy-*,*:savvy-*`; those definitions pin their own model, and the definition's model is not visible to hooks: UNVERIFIED). Modes (`/delegation warn|deny|off|status`, persisted in `$.store['guard:mode']`, default `warn`):
- warn: pass through, toast (limiter 30 s) `AGENT · NO MODEL SET: "{description}" started without a model. Add model: haiku or sonnet.`, add a violation row to the pane.
- deny: return `{deny: 'Agent call needs an explicit model. Set model to haiku (search, read, bulk), sonnet (build, tests, docs), opus or fable (hard design only). Policy: ~/.claude/CLAUDE.md. Retry the same call with model set.'}` without calling `next` (T:433). `.catch` passes through when `next.called`, otherwise re-runs the pure check and denies only if the model is missing.
- off: pass through, no toast, spend still tracked.
**Spend by tier (mockup 6).** From `turn.step` result `usage` (T:13530; fields T:6440-6444; `TurnUsage.model` T:13656), main and subagent steps both, tier = `modelFamily(usage.model)`. Cost per step = `(input*in + output*out + cacheRead*read + cacheCreation*write5m)/1e6` with `shared/prices.ts` (Q10: a static dated table with `asOf` and source, seed `savvy-progress register.tsx:299-305`, overridable through the plugin-level userConfig `pricesJson`; no network lookup, ever; cache writes priced at the 5m rate unless the TTL is known to be 1h). Pane: stacked horizontal bar, widths proportional to dollars, then per-tier label and `$` figures; line `Explicit model: {k} of {n} spawns`; footnote `estimate (prices as of {asOf}) · session total ${usd}` (`estimate (prices as of {asOf}, custom)` when `pricesJson` overrides rows) where `usd` is `session.measure.cost.usd` (T:10980) and the footnote gains `(differs {pct}%)` when the estimate and the total differ by more than 15%. Tiers: FABLE, OPUS, SONNET, HAIKU, OTHER (only if non-zero). Empty: `No spend yet`.
**Strings (terminal).** Pane: `DELEGATION GUARD · warn`, `SPEND BY TIER`, `[FFFFFFOOOOOOOOOOSSSSHH] 20 cells`, `FABLE $3.10 · OPUS $4.90 · SONNET $1.20 · HAIKU $0.15`, `⚠ AGENT · NO MODEL SET · research sweep · add model: haiku`. Band segment: `⚠ NO MODEL ×2` only when violations > 0 this session, else hidden.
**Wireframe (desktop pane 340x172, mockup 6).** Carrot-with-clipboard 40 px at top-left, `SPEND BY TIER`, 292 px bar (14 px high, tier colours, 1 px edges), tier captions and Space Mono `$`, then a tile with warn edge for the latest violation.
**Options.** `delegation.mode` warn, `delegation.allowTypes`, `delegation.toast` true, `pricesJson` (plugin-level userConfig string; override `{"asOf":"2026-10-11","opus":{"input":..,"output":..,"cacheRead":..,"write5m":..}}`; unknown keys ignored; invalid JSON ignored with one `$.ui.log` line and the built-in table stays), `delegation.minGapMs` 30000.

## 6. State and contract outline
```ts
export type Tier = 'fable'|'opus'|'sonnet'|'haiku'|'other'
export type PetRun = { id: string; agentId?: string; type: string; description: string; model: string; costume: PetCostume; status: 'running'|'done'|'failed'; startedAt: number; endedAt?: number; isBackfilled?: boolean; missed?: number; files: number; tests?: {pass: number; fail: number; skip: number}; reviewed?: boolean }
export type Spend = { byTier: Record<Tier, number>; main: number; subagents: number; steps: number; spawns: number; explicit: number; violations: {at: number; description: string}[] }
declare module 'claude-code' { interface PluginState { agents: { runs: PetRun[]; spend: Spend; ui: {autoOpened: boolean}; checklist: PetChecklist; guard: {mode: 'off'|'warn'|'deny'}; clock: number } } }
```
Store: `guard:mode` only (spend resets per session).

## 7. Hooks (all `.catch(next)` except the guard which follows conventions 3.4)
`session.start` (commands, load mode, sync, tick), `agent.spawn` (guard before `next`; after `next` record the run), `turn.step` generator (spend, pet model), `turn.complete` (finish run, enqueue review), `tool.call` (subagent files and tests; main checklist only when `showChecklist`), `prompt.submit` (checklist reset when enabled), `session.measure` (cost for footnote), `command.run{pets|review|delegation}`, `ui.render{AbovePrompt}`, `ui.render{Pane, requestId:'pets'|'delegation'}`.

## 8. Performance and privacy
No process execution. `$.agent.list()` at most every 3 s and only while a pet runs. Per-step arithmetic only. The pane keeps descriptions (already model-visible) and counts; no prompts, no answers, no file contents, no paths beyond counts. Prices file holds no secrets.

## F34 Nesting guard and runaway warning (2026-10-15)
Approved by the user 2026-10-15. Version bump `agents` 1.0.x to the next minor. Why: a past session cost over $1,000 over Oct 8-13: 430 subagents, 331 of them spawned BY subagents (depth 2); each started at about 60k context, the worst looped 100-280 calls with context at 700-960k; subagent cache reads and writes were about 88% of the cost. Two parts, both in the `delegation` mod, both warn-only by default, neither ever stops an agent by itself. Cite key: `D:n` = line in `.dev/plugin-authoring/types/claude-code.d.ts` (the copy `plugins/agents/tsconfig.json` compiles against; section 4 and 00-conventions use the `T:` numbering of build 2.1.295, re-grep the symbol if a number misses). `R:n` = `plugins/agents/hooks/register.tsx`.

### F34.1 Runtime API evidence
- **Caller of `agent.spawn` is known. CONFIRMED (typed).** `AgentSpawnInput.parentAgentId?: string` (D:317, doc D:310-316): "The id of the loop the spawn happens in (its `tool.call` `agentId`; for a subagent or teammate its `$.agent.list()` id); absent from main." Pinned (a hook cannot change it). Rule used here: `e.parentAgentId !== undefined` means the caller is a subagent (or teammate) loop; absent means the main loop. `AgentInfo.id` (D:114-130) states the same id is "a spawn inside it as `parentAgentId`", so the parent's row in `runs` is found by `r.agentId === e.parentAgentId` (R:656-657 stores `started.agentId`).
- **Fallback is not needed**, but if the live probe below shows `parentAgentId` missing on a nested spawn, the smallest alternative is a `tool.call` hook with matcher `{tool:'Agent'}` that reads `e.agentId` (`AgentLoop.agentId`, D:203, reserved/pinned; same hook shape the plugin already uses for subagent files, R:685) and stores `{toolUseId -> callerAgentId}` for the `agent.spawn` hook that follows (join key `AgentSpawnInput.tool_use_id`, D:271, "The Agent tool call this spawn belongs to"). That variant would run in `tool.call` before `next` and could return the deny itself.
- **Per-agent step usage. CONFIRMED (typed, and already used).** `turn.step` input `agentId?: string` (D:13463): "a subagent's id, the `id` `$.agent.list()` gives it and its `tool.call`s carry; absent on main". Result `usage: TurnUsage | null` (D:13530); `TurnUsage = ModelUsage & {model}` (D:13656); `input_tokens` D:6428, `cache_read_input_tokens` D:6440, `cache_creation_input_tokens` D:6444. The plugin's own `turn.step` generator (R:897-945) already computes `ctxTok = input + cache_read + cache_creation` and `turns` per run row; F34 reuses that arithmetic. Caveat in the typing (D:13459-13462): a subagent that a hook started through `$.agent.spawn` steps past THAT hook; every other plugin's hook sees it. Agents spawned by this plugin's own `$.agent.spawn` (none today) would be invisible to runaway tracking.
- **UNVERIFIED (live), with probe.** (a) That a model-called `Agent` tool inside a real subagent raises `agent.spawn` with `parentAgentId` set to that subagent's `agentId`, and that it equals the `agentId` later returned for the parent by its own spawn. Probe: temporary `on('agent.spawn')` that `$.ui.log`s `{parentAgentId, fork, isTeammate, workflow !== undefined}` to debug; main spawns a haiku subagent that is told to call Agent once; expect one line with a non-empty `parentAgentId` equal to the first spawn's `agentId`. (b) Whether a teammate's own `Agent` call and a workflow script's `agent()` carry `parentAgentId` (same probe, once with a teammate, once with a Workflow). (c) Whether engine-internal forks (compaction, memory; D:132-135 says their ids appear in no list) ever raise `agent.spawn`; same probe, run `/compact` and watch for lines.

### F34.2 Nesting guard (extends section 4)
**Behaviour.** In the `agent.spawn` hook, BEFORE the existing model check (guard order: nesting first, then the section 4 model check; the `.catch` of conventions 3.4 re-runs both pure checks). A spawn is NESTED when `e.parentAgentId !== undefined`. Mode (`nesting.mode`: `warn` default, `deny`, `off`) is independent of `guard:mode`.
- warn: pass through with the event unchanged, count it, add a pane row, and after `next` succeeded (not denied by another hook) toast once per `nesting.minGapMs` (limiter separate from the model-violation limiter and shared by all nested spawns): `AGENT · NESTED SPAWN: "{description<=50}" was started by subagent "{parent<=50}". Subagents should return to the orchestrator instead.`. `{parent}` is the description of the run whose `agentId` equals `parentAgentId`, else `agent {first 8 chars of parentAgentId}`.
- deny: return, without calling `next`, `{deny: 'Agent call refused: you are a subagent, and subagents must not start subagents. Stop now and do not retry this call. Return to the orchestrator with your result so far and say exactly what you still need (the task, the files or the information); the orchestrator will delegate it. Policy: ~/.claude/CLAUDE.md.'}`. Count it and add the pane row; no toast (the subagent, not the user, is addressed). Nested + model-less in deny mode: ONLY this deny, the model violation is not counted (nothing started).
- off: pass through, no toast, no row, no count.
**Which spawns it applies to (decided).** Forks are NOT exempt: a fork inherits the whole parent context, the most expensive nested case. `allowTypes` (section 4, `savvy-*`) is NOT consulted: it exists because those definitions pin a model, not because they may nest. Own exemption list `nesting.allowTypes` (glob, comma separated, default empty). Workflow-script spawns (`e.workflow !== undefined`, D:357) are exempt: a hook can only refuse them and they are not a model's choice. Teammate spawns (`isTeammate`) and spawns whose caller is a teammate are treated like any other nested spawn (open question 1).
**Command.** `/delegation nesting warn|deny|off` sets and persists: `Nesting guard: mode {m}.`; bare `/delegation nesting` prints `Nesting guard: mode {m} · nested spawns {n}`; any other argument prints `Usage: /delegation nesting warn|deny|off` and changes nothing. `/delegation status` text gains ` · nesting {m} · nested {n}` after the existing text (the old substrings stay). `/delegation warn|deny|off` does not touch the nesting mode. The command is registered exactly as `delegation` (collision fallback `agents-delegation` per conventions 1.6).
**Strings.** Pane (below the model-guard block, shown always): `NESTING GUARD · warn`; per row (latest 5, newest first): `⚠ AGENT · NESTED SPAWN · {description} · by {parent}`; empty: `no nested spawns`. Desktop: the same texts in a tile with warn edge; Svg `alt` equals the terminal text.
**Settings / store / state.** userConfig (conventions 12 spelling): `nesting_mode` (default `warn`, options warn|deny|off), `nesting_allowTypes` (default ``), `nesting_toast` (default true), `nesting_minGapMs` (default 30000). Store: `nesting:mode` = `{v:1, mode}` (same shape and loader as `guard:mode`, R:377-396; stored value beats the option default; invalid value falls back to the option). State: `guard` atom gains `nestMode`; `Spend` gains `nested: {at: number; description: string; parent: string}[]` (last 50) and `nestedCount: number` (session, not stored).

### F34.3 Runaway warning
**Behaviour.** For every `turn.step` result whose input has `agentId`, add 1 to that agent's `steps` (also when `usage` is null) and, only when `usage` is non-null, set its `ctx` to `input_tokens + cache_read_input_tokens + cache_creation_input_tokens` of THIS step (the latest step, not a sum, not the peak; output tokens excluded). Steps without `agentId` (main loop) are ignored. Thresholds: `runaway.maxSteps` (default 100) and `runaway.maxContext` (default 300000); a threshold fires when `steps >= maxSteps` or `ctx >= maxContext`; `0` disables that threshold. Each threshold fires AT MOST ONCE per agent for the session: setting `hitSteps` / `hitCtx` (ms epoch) the first time, never cleared while the agent exists, even if `ctx` later falls below the limit. On firing and if `runaway.toast` is true, show one toast per threshold crossed: `AGENT RUNAWAY · "{description<=50}" · {steps} steps · {ctxK}k ctx · consider stopping it` where `{steps}` and `{ctxK}` (`round(ctx/1000)`) are the values at that step, `{description}` is the run's description, else `agent {first 8 chars of agentId}`. Both thresholds crossing on one step = two toasts. No rate limiter (each toast is one-shot; at most 2 per agent). The plugin NEVER stops, interrupts, messages or denies anything because of a runaway: the only effects are the toast, the pet-row mark, the band segment.
**Pet row mark.** While the run is `running` and any threshold fired: terminal row gets ` · ⚠ RUNAWAY` after the `running mm:ss` word (`{costumeEmoji} {costume} · {type} · {tier} · running {mm:ss} · ⚠ RUNAWAY — {description}`); desktop row gets a warn-edged chip `RUNAWAY` and its Svg source contains `data-runaway="1"`; alt equals the terminal text. A done or failed row shows no mark.
**Band segment.** `⚠ RUNAWAY ×{n}` where n = number of RUNNING agents with at least one fired threshold; hidden when n is 0; terminal and desktop identical; priority class of the delegation segment (2), placed after it; the band row also shows when only this segment is non-empty (extends section 5's "any is non-empty"). Pressing it opens the `pets` pane.
**Settings / state.** userConfig: `runaway_maxSteps` (default 100), `runaway_maxContext` (default 300000), `runaway_toast` (default true). No store key (counters are per session). State: new atom `agents.runaway: Record<agentId, {steps: number; ctx: number; hitSteps?: number; hitCtx?: number}>`, capped at 200 agents (drop the oldest finished). `PetRun.turns` and `PetRun.ctx` (R:915-925) hold the same two numbers for finished-row display; the atom exists so a step that arrives before the run row is recorded is not lost.

### F34.4 Performance and privacy
Per step: two integer additions, two comparisons, one atom update (the same update that already writes `turns`/`ctx`); no `$.agent.list()`, no process, no I/O. The nesting check is a field read plus a Map lookup in the spawn hook. Toasts and the pane carry descriptions (already model-visible), counts and token numbers only, no prompts or paths (conventions 9).
