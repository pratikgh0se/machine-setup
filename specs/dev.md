# Spec: `dev` plugin (PR Radar, Git chip, Session Diff, Test Pulse, Coverage Delta, Typecheck Feedback, Port Watch)

Read `00-conventions.md` first. Board: `#swe-3` (PR Radar mockup), `#swe-5` (Typecheck chip mockup); others (#swe-6, 7, 13, 17, 18) have no mockup and are designed here. Version 1.0.0.

## 0. Purpose and mods
Makes the state of the code visible while agents work: branch, changes, tests, coverage, type errors, PRs and stray dev servers. Mods: `git`, `diff`, `pulse` (Test Pulse), `coverage`, `typecheck`, `pr`, `ports`. Band row (order): git, pulse, coverage, typecheck, pr, ports, diff. Panes: `pr-radar`, `changes`, `ports`. Commands: `/prs`, `/changes`, `/pulse`, `/coverage`, `/typecheck`, `/ports`. Toasts: exactly one kind, the PR Radar failing-check toast (section 4). Spends no tokens; Typecheck Feedback adds a few lines of text to a tool result.

## 1. Process layer (applies to every mod except `pulse`, `coverage` parsing)
Every mod below that says CONFIRMED (process-exec) uses `$.process.run` (T:3515). The types doc says "CLI only" (T:3493), but a live probe on 2026-10-11 ran `git --version` from a `tool.call` hook in a desktop session with exitCode 0: it works on both hosts, so this is the expected path. `shared/proc.ts` rules (conventions 8) keep a cheap defensive capability probe `git --version` at start; only if it ever rejects the mods `git, diff(git part), pr, ports, typecheck` show `needs host commands` once in `$.ui.status` and do nothing else; `pulse` and `coverage` keep working because they read tool results and files only. Repo context `repo.ts`: `TOP` = `git rev-parse --show-toplevel` from `$.session.cwd()` (T:2775; `$.session.repo()` T:2804 gives the MAIN tree's root and origin URL and is only used for the GitHub-remote check), refreshed on `classic.CwdChanged`. No repo: git, diff (tool-only mode), pr, coverage baseline degrade quietly; chips hidden.
Process budget: one family at a time, global cap 2 concurrent. Intervals: git >= 5 s apart (event driven), diff >= 5 s, pr >= 60 s, ports >= 15 s, typecheck per edit with lock. Nothing polls after `idleMinutes` (30) without user input.

## 2. Git chip (`git`)
**Data.** CONFIRMED (process-exec): `git status --porcelain=v2 --branch -z --untracked-files=normal` -> `# branch.head`, `# branch.upstream`, `# branch.ab +A -B`, entries `1`/`2` (changed: XY, staged if X != '.', unstaged if Y != '.'), `u` (conflict), `?` (untracked). Worktree: `git rev-parse --path-format=absolute --git-dir --git-common-dir` differ -> linked worktree, name = basename(TOP) (verified output shape locally). CONFIRMED trigger: Bash result `gitOperation` (commit/push/branch/pr, T:20392).
**Refresh.** `session.start`, main `turn.complete`, after Write/Edit/NotebookEdit success (debounced 1.5 s), after any non-read-only Bash or one with `gitOperation`, `classic.CwdChanged`; never a timer. Timeout 5 s; `git.untracked` option `normal|no` for huge repos.
**Strings.** Terminal `🌿 main* ↑2 ↓0 +3 ~5 ?1 · wt auth-flow` (`*` dirty; `+` staged, `~` unstaged, `?` untracked, `!` conflicts; `↑ahead ↓behind` only when an upstream exists; detached: `HEAD@abc1234`). Variants: full 330 px / 46 cells; `🌿 main* +3 ~5` 150 / 20; `🌿 main*` 90 / 10. Desktop: bevelled tile, branch in Space Mono 11, counts in Silkscreen; dirty marker warn colour, behind info colour, conflicts danger edge. States: HIDDEN (no repo), CLEAN, DIRTY, CONFLICT, ERROR (`git: error` dim).
**Options.** `git.minRefreshSec` 5, `git.untracked` normal, `git.showWorktree` true.

## 3. Session Diff (`diff`)
**Behaviour.** Chip `📝 5 files +120 −34`; pane `changes`: header `SESSION DIFF · 5 files · +120 −34 · since 14:02`, one row per file sorted by churn: status glyph (`A` `M` `D` `R`), repo-relative path (middle-clipped, Space Mono), `+x −y`, an 8-cell bar split add/del, and a `Link` `file://<abs path>` that opens it (https/http/file only, R:125). `/changes open <n>` runs `changes.openCommand` (default `open {path}`) via `proc.run`. Max 50 rows then `+N more`. Binary: `bin`.
**Data, primary (CONFIRMED, process-exec).** `snapshot.ts` (same plumbing as safety.md section 2 steps 1-4 with a temp index `claude-diff-S8.index`, never a commit): `BASE` tree at `session.start`; `CUR` tree after main `turn.complete` and after non-read-only Bash (>= 5 s apart). Then `git diff --numstat -z BASE CUR` and `git diff --name-status -z BASE CUR`. Tree-to-tree diff includes Bash edits (the gap in `/rewind`) and excludes dirt that predates the session. Between snapshots, touched paths from Write/Edit/NotebookEdit results (CONFIRMED, T:16278, T:16792, T:16402) are shown immediately with `~`.
**Data, fallback (CONFIRMED, tools only).** No repo or no process: add/del counts from the tool results' `structuredPatch` (Edit T:20518, Write T:21420: count lines starting `+`/`-`); label `(tools only)`. `bashEditDiff.changedFiles` (T:20412) is `@internal`: bonus only, never required (UNVERIFIED stability).
**Edge cases.** `/clear` resets BASE (`session.end{reason:'clear'}`); resumed session: BASE = tree at resume. > 2000 changed files: cap, `+N more`. Renames use `R`. **Options.** `changes.minRefreshSec` 5, `changes.maxRows` 50, `changes.openCommand`.
**Session Diff freshness (decided 2026-10-12).** `/changes` and the Session diff pane force a fresh snapshot (ignoring `changes.minRefreshSec`) before they render; the text response also lists up to 5 changed files as `path +a −d`. Totals are relative to the session-start tree, not HEAD.

## 4. PR Radar (`pr`)
**Behaviour.** Pane `pr-radar` (mockup swe-3): `{n} WORKTREES`, one row per worktree: name, `#PR`, a 10 px status block (ok = pass, warn = pending, danger = fail, slot = none), word `pass|running|fail|none`, review word `APPROVED|CHANGES|PENDING|-`, mergeable `CONFLICT` shown only when conflicting, PR title (clip 40, Chivo), `Link` to the PR. Band chip for the CURRENT branch's PR: `🔀 #412 ✅ checks · APPROVED` (fail: `⛔ checks`, pending `⏳ checks`, conflict adds `· CONFLICT`); hidden when the branch has no PR. Footer `updated 40 s ago`. Terminal pane lines: `wt/auth-flow  #412  pass  APPROVED`.
**Data (CONFIRMED, process-exec; flags verified against gh 2.98.0 on this Mac).** (1) `git worktree list --porcelain` (blocks `worktree`, `HEAD`, `branch refs/heads/x` or `detached`, `locked`, `prunable`). (2) ONE call per cycle: `gh pr list --state all --limit 100 --json number,title,author,headRefName,url,isDraft,state,reviewDecision,mergeable,mergeStateStatus,statusCheckRollup,updatedAt` with `cwd=TOP`. Map `headRefName` to each worktree branch; choose OPEN over MERGED/CLOSED, then newest `updatedAt`. Checks from `statusCheckRollup`: CheckRun `conclusion` in FAILURE, TIMED_OUT, CANCELLED, ACTION_REQUIRED, STARTUP_FAILURE or StatusContext `state` in FAILURE, ERROR = fail; CheckRun `status` != COMPLETED or StatusContext `state` PENDING/EXPECTED = pending; else pass; empty = none; overall fail > pending > pass. `reviewDecision` APPROVED, CHANGES_REQUESTED, REVIEW_REQUIRED, null. `$.session.repo().originUrl` must contain `github.com` else state `no GitHub remote`.
**Backoff.** Interval = max(60 s, `pr.intervalSec`); pending checks -> 60 s, all settled -> 180 s; no user input for 10 min -> x3; error -> x2 per consecutive failure up to 15 min; rate limit (stderr contains `rate limit`, HTTP 403/429, or Bash `ghRateLimitHint` T:20390) -> no call for 15 min; idle > 30 min -> paused until the next prompt. `/prs refresh` may bypass the interval but never goes under 15 s. `gh auth status` once at start (exit != 0 or ENOENT): state `gh: not signed in. Run gh auth login in a terminal.`, retry only after 10 min; when signed in, `gh api user --jq .login` once gives `me` (kept in memory, used for the toast below). No fetch for repos without worktrees (single tree = one row).
**Toast on a failing check (Q18).** When the overall checks of an OPEN PR authored by `me` (`author.login`) flip to `fail` from a previously observed `pass`, `pending` or `none`, `dev` raises ONE toast itself with `$.ui.toast(text, {timeoutMs: 8000})` (T:2447): `PR #418 · CHECKS FAILING: {title, clip 40}. Run /prs.` (glyph prefix by `toastGlyph(surfaces)`, <= 140 chars). Rules: (1) the first observation of a PR after start is a baseline and never toasts, so a PR that is already failing at session start stays silent; (2) no toast for `pass`, `pending`, `none`, ready-to-merge, approved, merged or conflict transitions; (3) a PR re-arms only after it has left `fail`; (4) PRs of other authors never toast (they still appear in the pane); (5) the toast is subject to the shared convention of `00-conventions.md` section 7.5: `createLimiter({minGapMs: 60000, peers: ['awareness.headsup']})` self-limits to 1 per minute, treats a peer toast less than 60 s old as a reason to queue, and publishes `dev.toast.lastShownAt`; (6) focus quiet mode: while `awareness.focus.phase === 'focus'` or `awareness.headsup.mutedUntil` is in the future the toast is HELD (not dropped) and shown when quiet ends if the PR is still failing, at most 60 min old; if several PRs are held, one toast `PR CHECKS FAILING · {n} PRs. Run /prs.`; (7) option `pr.toastOnFail` (default true) turns the feature off. Without `awareness` installed the peer atoms are absent and only rules 1 to 5 and 7 apply.
**States.** LOADING, OK, STALE (> 3x interval), NO_GH, NO_REMOTE, RATE_LIMITED (`rate limited until HH:MM`), ERROR. **Privacy.** `gh` runs with the user's own auth; stdout is parsed and dropped; only number, state words, branch, title (<= 60 chars, `$.state` only) and URL are kept. **Options.** `pr.enabled` true, `pr.intervalSec` 60, `pr.maxPrs` 100, `pr.toastOnFail` true.

## 5. Test Pulse (`pulse`)
**Behaviour.** Chip after each recognised test run (main thread; `pulse.includeSubagents` false): `🧪 12 pass 3 fail 1 skip · 2.3s · pytest` (`fail`/`skip` omitted when 0; duration `120ms` under 1 s). After a later successful Write/Edit/NotebookEdit the chip appends ` · stale (2 edits)`. Flaky: ` · ⚠ 1 flaky`. Desktop: chip tile with 2 px edge ok/danger. `/pulse`: last 5 runs and flaky candidates `name (flips 3)`.
**Data (CONFIRMED).** Bash `tool.call` result `stdout`/`stderr` (T:20352) plus `e.command` (T:16190). No exit code field exists (T:20350-20440): `isError` is used only as a hint (UNVERIFIED that non-zero sets it). ANSI stripped.
**Runner detection on `e.command`:** `pytest|py.test|python -m pytest|uv run pytest` -> pytest; `vitest`; `jest`; `bun test`; `go test`; `cargo test|cargo nextest run`; `npm|pnpm|yarn [run] test` -> unknown (try all parsers).
**Parsers (`shared/testparse.ts`, pure, also used by `agents`):**
- pytest: summary line `=+ ... in 2.31s =+` or quiet `3 failed, 12 passed in 2.31s`; tokens `(\d+) (passed|failed|skipped|error|errors)`; names `^FAILED (\S+)`.
- vitest: `Tests  2 failed | 10 passed (12)`, `Duration  1.52s`; names ` FAIL  file > name`, `× name`.
- jest: `Tests:  1 failed, 9 passed, 10 total`, `Time:  2.1 s`; names `● suite › name`.
- bun: ` 10 pass`, ` 1 fail`, ` N skip`, `Ran 11 tests across 2 files. [120.00ms]`; names `(fail) name`.
- go: `ok  pkg 0.123s` / `FAIL pkg 0.5s`, `--- FAIL: TestX`; counts packages and the chip reads `1 pkg pass 1 pkg fail` (with `-v` it counts `--- PASS`/`--- FAIL` tests and drops `pkg`).
- cargo: sum every `test result: ok|FAILED. P passed; F failed; I ignored; ... finished in T s`; names `test a::b ... FAILED`.
No summary: command matched a runner -> `ran, no summary` (dim); otherwise ignore the result.
**Rewritten output (decided 2026-10-12).** Tool output may be rewritten by compression hooks such as RTK, so the result text is not always the runner's own output. Parsers MUST also accept RTK summaries: go `Go test: P passed, F failed in K packages` plus `[FAIL] Name` lines (counts are tests, not packages) and `Go test: No tests found`; pytest `Pytest: N passed, M failed` and `Pytest: No tests collected`. When a recognised runner yields no summary, the exit status decides the chip: a leading `Exit code N` line (N != 0) -> `ran, failed (exit N)`; no failure marker and no error flag -> `ran, ok`; otherwise `ran, no summary`.
`/pulse` lists the names of failing tests from the last run when the output names them (up to 5, then `+N more`).
**Flaky rule.** Keep the last 20 runs per runner. A test name failed in run k and is absent from the failures of run k+1 of the same runner (the run had a summary) with zero successful edits between them (counter `editsSince` from Write/Edit/NotebookEdit results) = one flip; flips persist as `$.store['pulse:flaky:<repoHash>']` `{name: flips}` (`repoHash` = FNV-1a of TOP, no path stored), decay after 14 days; flaky = flips >= 2. **Options.** `pulse.includeSubagents` false, `pulse.flaky` true, `pulse.maxNames` 20.

## 6. Coverage Delta (`coverage`)
**Behaviour.** Chip next to Test Pulse after a run: `📈 83.2% (+0.4)`; a drop beyond `warnDropPts` 1.0 uses the warn colour/`⚠`. `/coverage`: totals, delta, baseline kind and time, worst 3 changed files (lcov only). No file: chip hidden, `/coverage` says `No coverage file found. Run the tests with coverage (vitest --coverage, pytest --cov).`
**Data (CONFIRMED: `$.fs.exists/stat/read` T:3242, T:3321; formats are derived).** After a recognised test run look under `TOP` in order: `coverage/coverage-summary.json` (istanbul: `total.lines.pct`, else `statements.pct`), `coverage/lcov.info`, `lcov.info`, `coverage.xml` / `coverage/cobertura-coverage.xml` (root `line-rate`, regex on the first 2 KB), `coverage.json` (coverage.py: `totals.percent_covered`). Accept only if `mtimeMs >= runStart - 2000`. lcov: sum `LF`/`LH` (lines), `BRF`/`BRH`, `FNF`/`FNH`; per-file `SF:` blocks. Files over 4 MiB are skipped with a note (T:3242 cap).
**Baseline (Q16).** `coverage.baseline` = `session-first` (DEFAULT: the first coverage reading this session is the baseline, kept in `$.state` only) or `last-clean` (opt-in, `$.store['cov:base:<repoHash>']`, written when `git status --porcelain` was clean at run time; process-exec). Delta in percentage points, one decimal, sign shown. Changed files for the per-file view come from the Session Diff data. **Options.** `coverage.baseline`, `coverage.warnDropPts` 1.0, `coverage.metric` lines|statements.

## 7. Typecheck Feedback (`typecheck`)
**Behaviour (Q15: after EACH edit, not once per turn).** After a successful Write/Edit/NotebookEdit (any loop, so subagent edits are checked too) the plugin runs the right checker on the touched file (incremental `tsc`, `ruff`/`eslint` on the file, 20 s budget for tsc and 8 s for the others) and appends the errors to THAT call's result as `context` (T:12735: what the model reads after the tool's result), so the agent fixes them. Never denies, never changes `result`. Band chip (mockup swe-5): `⚠ TSC 2 errors · fed back to Claude`; clean after errors: one `context` line `TYPECHECK: clean (tsc).`; chip hidden when clean.
**Checkers (CONFIRMED, process-exec).**
- `.ts .tsx .mts .cts`: nearest `tsconfig.json` upward from the file (`$.fs.exists`, stop at TOP); binary `TOP/node_modules/.bin/tsc` if it exists, else `npx --no-install tsc`; `tsc --noEmit --incremental --tsBuildInfoFile <git-path claude-tsc-<hash>.tsbuildinfo> -p <tsconfig>`; output lines `file(line,col): error TSxxxx: message`. Not found: disabled, status `tsc: n/a`.
- `.py`: `ruff check --output-format=concise <file>` (probe `ruff --version` once; fallback `python3 -m ruff`).
- `.js .jsx .mjs .cjs .ts .tsx` with an eslint config in TOP (`eslint.config.*`, `.eslintrc*`) and `node_modules/.bin/eslint`: `eslint --no-warn-ignored -f json <file>`; messages with `severity 2` only.
**Feedback shape.** Errors in files edited this session (set from edit results) first, up to `maxLines` 10 and 2000 characters: `TYPECHECK: {n} error|errors in files you touched ({tool}):` (singular for 1) then `src/a.ts(10,5): TS2322 Type 'string' is not assignable to type 'number'.` lines, then `(+N errors in other files)`. Only error text, never source lines. De-dup: the same (file, message) set as the last feedback to that loop is not repeated; it is resent when a touched file's errors change.
**Run policy.** Lock per kind; edits arriving during a run set `pending` and trigger one more run. Budget in the hook after `next`: tsc `timeoutSec` 20, ruff/eslint 8; when exceeded the result is returned unchanged, the run finishes in the background and its outcome goes to the chip and to the NEXT edit's feedback. Modes `tc.mode` = `context` (default) | `band` (chip only) | `off`. The first incremental tsc run in a big project can take a minute: it is therefore always allowed to finish in the background. Circuit breaker per checker.
**Options.** `tc.mode`, `tc.tsc|ruff|eslint` true, `tc.timeoutSec` 20, `tc.maxLines` 10. UNVERIFIED: that a hook-added `context` reaches the model (type says so, T:12735); acceptance step (manual c).

## 8. Port Watch (`ports`)
**Behaviour.** Chip `🔌 2 ports (3000, 5173)` when agent-started listeners exist; pane `ports`: section OURS (listeners that appeared since session start AND whose cwd is under TOP or a worktree of the repo): `:3000  node  pid 4242  age 12 min  [STOP]`, then `{n} other listeners` collapsed. Age >= 30 min adds `stale?`. `STOP` (Q17: enabled, `ports.kill` true) is two-step: the first press arms it for 5 s and relabels it `CONFIRM`; the second press within 5 s re-verifies pid, port and cwd and then runs `kill -TERM <pid>`. It exists ONLY for OURS, i.e. processes started by Claude's agents (appeared since session start and cwd under TOP or a worktree); the `{n} other listeners` are list-only: no button, no kill path in the code; 3 s later reports `stopped` or `still running`. No `-9`.
**Data (CONFIRMED, process-exec, macOS; verified output shape).** `lsof -nP -iTCP -sTCP:LISTEN -Fpcn` -> lines `p<pid>`, `c<command>`, `f<fd>` (ignored), `n<addr>:<port>` (dedupe by pid+port; `*:3000`, `127.0.0.1:5432`, `[::1]:3000`). Then one call `lsof -a -p <pid,pid> -d cwd -Fpn` for the cwd of each. Baseline snapshot at `session.start`. Never `ps` with args: command lines can hold secrets; only the short command name `c` is shown.
**Cadence.** Scan at `turn.complete` and 3 s after a Bash that matches `dev|start|serve|run|nohup|&` or `run_in_background`; while the pane is open every 15 s; with >= 1 OURS and the pane closed every 60 s; otherwise no polling. **Options.** `ports.enabled` true, `ports.stale.min` 30, `ports.kill` true.

## 9. UI placement
Band row order `[git][pulse][coverage][typecheck][pr][ports][diff]`; priorities (1 = keep longest): typecheck 1, pulse 2, git 3, pr 4, coverage 5, ports 6, diff 7. Panes: `pr-radar`, `changes`, `ports`, opened by their commands or by pressing the chip. `$.ui.status` fallback: `main* · 12 pass 3 fail · 2 tsc errors`.

## 10. State and contract outline
```ts

// shared/peers.d.ts (read-only slices of awareness): PluginState['awareness']: { headsup: { lastShownAt?: number; mutedUntil?: number }; focus: { phase: 'idle'|'focus'|'break'|'paused' } }
```
Store: `pulse:flaky:<repoHash>`, `cov:base:<repoHash>` (only with `coverage.baseline=last-clean`). All `{v:1,...}`.

## 11. Hooks (`.catch(next)`, `next` always called)
`session.start` (probe, repo, BASE snapshot, port baseline, `gh auth status`, commands), `tool.call` (one dispatcher after `next`: git-refresh marks, edit counters, test parsing, typecheck run and `context` append, port scan scheduling), `turn.complete` (git, diff, ports scans), `classic.CwdChanged`, `session.end` (clear resets), `command.run{prs|changes|pulse|coverage|typecheck|ports}`, `ui.render{AbovePrompt}`, `ui.render{Pane, requestId:'pr-radar'|'changes'|'ports'}`, one `$.clock.every` driver (5 s granularity) for pr/ports scheduling. `$.ui.toast` is called from the PR cycle only (failing-check transition).

## 12. Performance and privacy summary
Hook overhead after `next` <= 300 ms except Typecheck Feedback (<= 20 s, only for edits of checkable files). Worst-case background load: 1 `gh` call/min, 1 `lsof` pair/15 s with the pane open, a few `git` calls per turn. Secrets: no command arguments, env, `gh` tokens, source lines or file contents in state, toasts or logs; test names and paths are the most detail kept.

## 13. Behaviour contract (code-blind tester)
Process output is mocked per argv. "chip text" = band text on terminal (= Svg alt on desktop).

Detached head fixture -> `HEAD@abc1234`. 3. Linked worktree (`--git-dir` != `--git-common-dir`) -> `wt auth-flow`. 4. Edit result for `src/x.ts` before the next snapshot -> pane lists `src/x.ts`. 7. **Test Pulse.** 8. ## Build clarifications (orchestrator, 2026-10-12, from the contract referee)
- Band text equality: tests assert terminal text == desktop alt at widths where every shown chip fits (~220 columns for the seven-chip row); at narrower widths only the priority/drop order is asserted.
- Go `-v` detection (s5): verbose = `-v`/`-test.v` in the command, or any `--- PASS:` / `=== RUN` line in output. `--- FAIL:` lines alone do not mean verbose; non-verbose chip reads per package (e.g. `1 pkg pass 1 pkg fail`).
- Trigger coalescing (s2, conventions s8.3): event triggers are trailing-edge coalesced; two triggers within 5 s cause ONE git status call in total; first refresh lands within 5 s of the first trigger; runs stay >= 5 s apart. Same for diff snapshots.
