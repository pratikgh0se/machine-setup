# Spec: `safety` plugin (Protected Files, Auto-checkpoint)

Read `00-conventions.md` first. Board: `#swe-2` (Protected Files, toast mockup "FILE PROTECTED"), `#swe-20` (Auto-checkpoint, no mockup). Version 1.0.0. Adopted tools (dcg, ggshield, tdd-guard) are not part of this plugin.

## 0. Purpose and mods
Stops edits to files that must not be hand-edited and keeps a rollback trail of the working tree without touching the user's branch or index. Mods: `protect`, `checkpoint`. No band row. One `$.ui.status` line (`🔒 protected · 📸 checkpoint #12 · 3 min ago`). Commands: `/protect`, `/checkpoint`. Spends no tokens.

## 1. Protected Files (`protect`)
**Behaviour.** A gating `tool.call` hook denies writes to protected paths, in the main loop and every subagent loop (`agentId` ignored). Deny returns `{deny: text}` (T:12710) so the model reads the text as the tool's error and does not retry blindly. Mode `deny` (default) | `warn` (pass through, toast only) | `off`.
**Default protected set (groups; each can be switched off by option).**
- `env`: any file whose basename matches `^\.env($|\.)` anywhere, except `allow` entries `.env.example`, `.env.sample`, `.env.template`, `.env.*.example`, `.env.*.sample`.
- `lockfiles`: basename `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `bun.lock` (Bun 1.2 text lockfile, Q11), `bun.lockb`, `Cargo.lock`, `poetry.lock`, `uv.lock` anywhere.
- `vault`: `{VAULT}/Boards/Engineering.md`, `{VAULT}/.obsidian/**`, `{VAULT}/Ledger/**` where `VAULT` = `$.env.get('OBSIDIAN_VAULT_PATH')` (T:3598) else `~/second-brain` (`HOME` from `$.env.get('HOME')`); both the spelling and the resolved `realPath` are used.
- extra: `protect.globs` option (comma list, gitignore-like globs `*`, `**`, `?`, absolute or `~` or repo-relative) plus runtime additions in `$.store['protect:extra']` made with `/protect add`.
**Tools checked.** `Write`, `Edit`, `NotebookEdit` (`notebook_path`), and `MultiEdit` if the build has it (compared with `String(e.tool)`; this 2.1.295 build has no MultiEdit: no match in `T`). Path fields: `file_path` (T:16278, T:16792), `notebook_path` (T:16402). All CONFIRMED. `Bash`: best effort, see below. MCP write tools (desktop-commander `write_file`, obsidian note tools) are NOT covered in v1 (Q12); `protect.mcpRules` (JSON `[{"tool":"mcp__x__y","arg":"path"}]`) exists only as an opt-in, default empty `[]`, because argument names are UNVERIFIED; with the default no MCP call is ever inspected or denied.
**Path resolution (pure function `resolveTarget` plus `$.fs.stat`).** Expand `~`; join relative paths to `$.session.cwd()` (T:2775); collapse `.` and `..`; then `$.fs.stat(path, {resolve:true})` (T:3321, doc example R:165): if it exists use `realPath`; if not, stat the parent folder and use `parent.realPath + '/' + name`; if unresolvable keep the normalized spelling. A path is protected if EITHER the normalized spelling OR the realPath matches (so a symlink named `x` that points to `.env` is caught; a hard link is not, documented). Comparison is case-insensitive when `protect.caseInsensitive` (default true; macOS).
**Bash (best effort, never complete).** Split the command on `;`, `&&`, `||`, `|`, newlines outside quotes; for each simple command extract write targets: redirects (`>`, `>>`, `>|`, `&>`, `N>`), `tee [-a]` args, `sed -i`/`--in-place`/`perl -i` file args, `cp|install|ln|rsync` destinations, `dd of=`, and (Q14) the shell DELETES and MOVES that target a protected file: `rm`, `unlink`, `shred`, `truncate`, `git rm`, `trash` operands, and BOTH the source and the destination of `mv` (so `mv .env x` and `mv x .env` are denied). Flags (`-f`, `-rf`, `-i`, `--`) are skipped. Not detectable (documented limit): a directory operand that merely contains a protected file (`rm -r .`), `find ... -delete`, `git clean`, globs and `$VAR` operands other than the literal-basename rule. Targets are resolved as above. A target containing `$`, a backtick or a glob metacharacter is unresolvable: allowed, unless its literal basename text is itself protected (e.g. `$DIR/.env` -> deny). Opaque code (`python -c`, `node -e`, heredoc scripts) is allowed. Package managers legitimately rewrite lockfiles: `npm|pnpm|yarn|bun|cargo|poetry|uv|pip ...` commands extract no targets and are always allowed; only a direct write by redirect or `cp/mv/sed -i` is denied. This is a guard against mistakes, not against an adversary.
**Directory tracking.** Within one Bash command the extractor tracks the working directory: it starts at `$.session.cwd()`; `cd`, `pushd`, `popd`, bare `cd` (HOME) change it for the rest of the enclosing scope (a `( ... )` subshell or a pipeline segment drops the change); relative targets are resolved against the tracked directory and shown as absolute paths in the deny text and the `/protect allow` hint. If the directory becomes unknown (`cd $VAR`, `cd -`, backticks, globs, an unparsable `cd`), relative targets are judged by the literal-basename rules only (env, lockfiles), and the deny text prints the target as typed, with the hint `/protect allow <spelling> 10m` and the note `directory could not be determined`. After `cd X` joined with `;`, newline or `||` (the cd may have failed) a relative target is checked against both the previous and the new directory; after `&&` against the new one only. `git -C <dir>` is treated like `cd <dir>` for that command. Relative extra rules (`protect.globs`, `/protect add`) containing a `/` are anchored to the session cwd at check time and do not match the same relative path under another directory: with cwd `/work` and rule `secrets/**`, `cd /elsewhere && echo X > secrets/a.txt` targets `/elsewhere/secrets/a.txt` and is allowed unless an absolute or basename rule matches. The built-in basename groups (`.env*`, lockfiles) still match anywhere.
**Deny text** (templated, no file contents): `Protected file: {path} ({reason}). Edit blocked by the safety plugin. {fix} To allow it once, ask the user to run: /protect allow {path} 10m`. Reasons/fixes: env `may hold secrets` / `Ask the user to edit it, or change .env.example.`; lockfile `lockfile managed by the package manager` / `Change dependencies with npm/pnpm/yarn/bun/cargo/poetry/uv so the lockfile stays consistent.`; vault Engineering.md `generated file` / `Edit its source or regenerate it as the vault's _CLAUDE.md says.`; `.obsidian` `Obsidian app settings` / `Use the Obsidian app.`; Ledger `protected vault folder` / `Ask the user.` Bash variant starts `Protected file: this command writes to {path} ...`; the delete variant starts `Protected file: this command deletes {path} ...` and the move variant `... moves {path} ...`; every variant ends with the override sentence (`To allow it once, ask the user to run: /protect allow {path} 10m`), so the model can tell the user exactly what to type (Q14).
**Override.** `/protect allow <path|glob> [duration]` (user-typed command; the model cannot run plugin commands): duration `10m` default, `60m` max (`protect.maxAllowMin`), kept only in `$.state` (never persisted, gone at session end), exact path or glob. `/protect list` (effective set, active allowances with minutes left), `/protect add <glob>`, `/protect remove <glob>` (only extras), `/protect status` (mode, blocked count, last block), `/protect off|warn|deny`.
**Toast.** On each deny: `⛔ FILE PROTECTED · Edit blocked: {relative path} is {reason short}.` (emoji only if no desktop surface), limited to 1 per path per 30 s; warn mode toast reads `FILE PROTECTED · {path} edited anyway (warn mode).` Counts in state.
Toast text: `{relative path}` is relative to the session cwd when the file is under it, else to the vault root when under it, else the absolute path. `{reason short}` is a noun phrase that reads after `is`: env `a secrets file`, lockfile `a managed lockfile`, Engineering.md `a generated file`, `.obsidian` `Obsidian app settings`, Ledger `a protected vault folder`, extra `a protected path`. The model-facing deny text keeps the full reason and absolute path.
**Failure mode.** `.catch(($, e, next) => next.called ? next(e) : ...)`: re-run the pure matcher on `e` alone (no `$`); deny if it matches a LITERAL basename or absolute rule; otherwise `next(e)`. A bug therefore never blocks unrelated edits and never lets a literal `.env` write through. Behaviour under `bypassPermissions` mode is UNVERIFIED (hooks run before the permission decision per T:3969 docs; confirm in the manual list).
**Cadence/perf.** Per call: pure matching plus at most two `$.fs.stat` (< 10 ms). No process, no timers.
**Options.** `protect.mode` deny, `protect.group.env|lockfiles|vault` true, `protect.globs` "", `protect.allow` the env exceptions, `protect.bash` true, `protect.maxAllowMin` 60, `protect.caseInsensitive` true, `protect.mcpRules` "[]".

## 2. Auto-checkpoint (`checkpoint`)
**Behaviour.** After a main-thread turn that changed files, the working tree (tracked changes AND untracked-not-ignored files) is committed to a side ref `refs/checkpoints/<session>`, a chain of commits, without moving HEAD, the branch, the real index, the stash or any file. Quiet: no toast on success; one toast on first failure (`📸 CHECKPOINT · FAILED: {reason}.`). `/checkpoint` shows `count, last time, ref`; `list` (last 10: `#n hh:mm +add -del files`); `diff <n>` prints the `git diff --stat` of checkpoint n against the working tree; `now` forces one; `restore <id> [path]` only PRINTS the exact command (`git restore --source=refs/checkpoints/<sid>~k --worktree -- <path>`; Q13); it never runs it, there is no option or flag that makes it run, and the plugin's allowed git subcommands do not include `restore`.
**Triggers.** `turn.complete` with `agentId` undefined (T:13324) when `dirty` and `now - lastAt >= minIntervalSec` (120). `dirty` is set by any successful Write/Edit/NotebookEdit result in any loop, by any Bash result without `isReadOnly` (T:12759), or by `bashEditDiff.changedFiles` (T:20412, `@internal`, bonus only). Also `/checkpoint now`. Not at `session.end` (its bound is short).
**Exact plumbing** (all via `proc.run`, T:3515; `env` merges over the host environment, T:8008; `cwd` = top level; hooks off per T:3505). Let `SID` = `$.session.id()` (T:2796) reduced to `[A-Za-z0-9_-]`, `S8` its first 8 chars.
1. `git rev-parse --path-format=absolute --show-toplevel --git-path index --git-path claude-ckpt-S8.index --git-path index.lock` -> four lines `TOP`, `IDX`, `TMP`, `LOCK` (verified). Not a repo or bare: mod `unavailable`. If `LOCK` exists (a git command is running): skip this round.
2. `cp -p IDX TMP`. (Keeps the stat cache so step 3 only hashes changed files; if IDX is missing, `git read-tree HEAD` with `GIT_INDEX_FILE=TMP`, or `read-tree --empty` on an unborn branch.)
3. With env `{GIT_INDEX_FILE: TMP}`: `git add -A -- . ':(exclude,glob)**/.env*' ':(exclude,glob)**/*.pem' ...` (pathspecs from `checkpoint.exclude`, default `.env*,*.pem,*.key,*.p12,id_rsa*,*.sqlite,*.kdbx`; the exclude pathspecs were verified to drop `.env.local` and `*.pem`). If it fails with an index error (torn copy): `git read-tree HEAD` into TMP, retry once.
4. With the same env: `git write-tree` -> `TREE`.
5. `git rev-parse -q --verify refs/checkpoints/SID^{tree}` -> `LASTTREE`; if none, compare with `git rev-parse HEAD^{tree}`. Equal to `TREE`: no change, delete TMP, done (no empty checkpoints).
6. `PARENT` = current `refs/checkpoints/SID` commit, else `HEAD` (none on an unborn branch). `git commit-tree TREE [-p PARENT] -m "checkpoint S8 #N <ISO time>"` with env `GIT_AUTHOR_NAME=claude-checkpoint GIT_AUTHOR_EMAIL=checkpoint@localhost GIT_COMMITTER_NAME=claude-checkpoint GIT_COMMITTER_EMAIL=checkpoint@localhost` -> `C`.
7. `git update-ref -m "claude checkpoint" refs/checkpoints/SID C [OLD]` (OLD = the previous value so a race fails instead of overwriting).
8. `rm -f TMP`.
Allowed git subcommands, nothing else: `rev-parse, ls-files, add, write-tree, read-tree, commit-tree, update-ref, for-each-ref, diff, log, cat-file`, plus `cp` and `rm -f` on the temp index. Never: `stash, commit, reset, checkout, restore, clean, rm, gc, push, fetch`. `git add` / `read-tree` / `write-tree` are never run without `GIT_INDEX_FILE` pointing at TMP.
**Verified 2026-10-11** (git 2.50.1 Apple Git-155, scratch repo with a modified tracked file, a staged file with further unstaged edits, an untracked file and an ignored file): HEAD, `shasum .git/index`, `git status --porcelain=v2`, `git stash list` and a hash of the worktree files were identical before and after steps 1-8; the checkpoint tree held the modified, staged and untracked files (with the unstaged edit) and not the ignored one; a second run with no change produced the same tree (step 5 detects it). `git stash create` was rejected: it left the stash list empty but rewrote `.git/index` (checksum changed) and omits untracked files. The builder re-runs this check as `scripts/verify-checkpoint.sh` (acceptance).
**Guards.** Skip when `git ls-files -o --exclude-standard` lists more than `checkpoint.maxUntracked` 2000 files: state `capped`, one toast `📸 CHECKPOINT · SKIPPED: {n} untracked files. Add build output to .gitignore.`. Timeout 20 s per run; circuit breaker (conventions 8.2). Cap `maxPerSession` 500 (then state `capped`). Retention: at `session.start`, `git for-each-ref --format='%(refname) %(committerdate:unix)' refs/checkpoints` and `git update-ref -d` refs older than `keepDays` 14. Objects stay reachable through the refs, so `git gc` keeps them until pruned; `refs/checkpoints/` is outside the default push/fetch refspecs.
**Edge cases.** Linked worktrees: `--git-path` resolves per-worktree, so each worktree session has its own TMP and the shared ref namespace is keyed by SID. Submodules are recorded as gitlinks (not their content). Merge/rebase in progress: allowed (real index untouched). Large binaries: `core.bigFileThreshold` is respected by git; excludes above apply. Empty repo: first checkpoint has no parent. Process execution unavailable (defensive only: `$.process.run` is CONFIRMED on desktop and CLI, probe 2026-10-11): state `unavailable`, status text `📸 needs host commands`, nothing else.
**Status from the ref.** `/checkpoint` status derives `count` (from the `#N` in the tip commit message, never lower than the stored counter), `last` (committer time) and `tree` (tip tree, 7 chars) from the ref tip when the in-memory view has none (new process or resumed session). A checkpoint ref may be created in any session whose first snapshot differs from HEAD, including repos with pre-existing uncommitted files; this is intended. The default exclude `.env*` also keeps `.env.example` out of snapshots.
**Options.** `checkpoint.enabled` true, `checkpoint.minIntervalSec` 120, `checkpoint.keepDays` 14, `checkpoint.maxUntracked` 2000, `checkpoint.maxPerSession` 500, `checkpoint.exclude`, `checkpoint.statusLine` true.

## 3. UI placement and text wireframes
No band. Toasts: protect deny (per path), checkpoint failure (once). Status line (`$.ui.status`): `🔒 protect: deny · 2 blocked · 📸 #12 3 min ago`. `/protect status` text:
```
PROTECTED FILES · deny
groups  env on · lockfiles on · vault on
blocked 2 this session · last: package-lock.json 4 min ago
allow   (none)
```
`/checkpoint` text: `CHECKPOINTS · ref refs/checkpoints/ab12cd34 · 12 saved · last 3 min ago · tree 9f3c2a1`.

## 4. State and contract outline
```ts
export type ProtectView = { mode: 'off'|'warn'|'deny'; blocked: number; last?: {path: string; at: number; group: string}; allowances: {pattern: string; until: number}[]; extras: string[] }
export type CheckpointView = { state: 'unavailable'|'idle'|'running'|'ok'|'capped'|'error'; count: number; lastAt?: number; lastTree?: string; ref?: string; dirty: boolean; error?: string }
declare module 'claude-code' { interface PluginState { safety: { protect: ProtectView; checkpoint: CheckpointView; clock: number } } }
```
Store keys: `protect:extra` (string[]), `checkpoint:n:<sid>` (counter), `protect:mode`.

## 5. Hooks
`session.start` (commands, vault root, git probe, prune refs), `tool.call` x2: the gate (before `next`, `.catch` per section 1) and a dirty marker (after `next`, never changes the result), `turn.complete` (checkpoint), `command.run{protect|checkpoint}`, `session.end` (flush counter). Both `tool.call` hooks call `next(e)` for allowed calls.

## 6. Performance and privacy
Gate < 10 ms. Checkpoint: one run per >= 120 s; typical repo < 1 s; two `git` processes at most in parallel never. Denied paths are shown relative to the repo/vault, never contents. Checkpoint objects never leave `.git`; excludes keep keys and `.env*` out; untracked files that are not ignored and not excluded are stored locally (README warns).

## 9. Decisions (closed 2026-10-11)
11. **Q11** `bun.lock` is in the lockfile group (with `bun.lockb`).
12. **Q12** MCP write tools are NOT covered in v1; `protect.mcpRules` exists as an opt-in, default empty.
13. **Q13** `/checkpoint restore <id>` PRINTS the exact git command; it never runs it.
14. **Q14** `rm`/`mv` (and `unlink`, `shred`, `truncate`, `git rm`, `trash` where detectable) targeting protected files are denied too; the deny message explains the `/protect allow` override.
